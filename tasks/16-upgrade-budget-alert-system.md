# Task 16 (PRIORITY): Upgrade budget error and dependency alerts

**Status:** Audit complete, implementation pending · **Suggested branch:** `codex/upgrade-budget-alert-system`

## Why

BillBuild checks German tenders and displays cap proximity for priced lists. The workspace assessment runs once on the imported list. A quantity, price, category, cap or phase edit can change the current budget without a new assessment. The normalized BOM API has stronger database integrity controls and an outdated flag. It has a separate trigger and storage model.

**LLM Layer Status (Layer 3): INACTIVE by default, conditionally ACTIVE for eligible uploads with an explicitly configured provider, live provider UNVERIFIED. Coverage reporting is BROKEN and reproduced offline.** The repository implements model calls in the upload worker. The checked-in Compose configurations disable them by default. The current deployed credentials, model availability and provider response quality remain unverified.

Fix three problems first: stale reports and missing source-total evidence in `backend/workspace_analysis.py`, unsafe traversal of cyclic sections in `backend/analysis/layer1/arithmetic.py`, and misleading AI completion indicators in `backend/analysis/layer3/common.py` and `frontend/src/pages/ListPage.tsx`. Existing change-order signals estimate tender risk. The report inputs do not provide authoritative commitments, actuals, forecasts, approved changes or contingency balances.

## Error and dependency detection gaps

- **Rollups and provenance.** `backend/analysis/layer1/arithmetic.py` checks stated line amounts (commercial cent rounding and 0.01 tolerance) and section/net totals (0.05 tolerance, including discounted or lump-sum child totals). `_counted_amount` omits missing source amounts and `_SectionSums` puts unknown parents/sections at root. `workspace_analysis._uploaded_input` and `_attach_source` preserve some line amounts and flags but omit stated section/net totals and discount/lump-sum rollup evidence. `adapter.from_db` builds sections without stated totals. Source absence or wholly ambiguous joins can produce no notice. Compare original statements and current calculated amounts with explicit coverage.
- **Fields and numbers.** `backend/analysis/layer1/{completeness,consistency,pricing}.py` covers missing/negative/zero quantity, required fields, duplicate OZ, some orphan/alternative cases, distribution sums, pricing and unit/currency mismatches. `adapter.from_data` converts invalid/non-finite line numbers to missing with an import warning and `workspace._dumps` rejects non-finite JSON. Gaps include negative rate/amount policy, bounds, locale ambiguity, missing versus zeroed input, broken references and a vetted WBS/cost-code mapping. Attached PDF/XLS warnings can replace snapshot warnings. OZ identifies a position within source context.
- **Structural links.** `workspace_analysis.prepare` rejects children before their parents, even on valid acyclic input. `adapter.from_data` checks unique IDs but lacks general graph validation. Section/area ancestry, line alternatives, revisions and tender→offer→award links require distinct edge rules. Invalid draft or imported graphs can throw in L1 traversal or disappear from the root rollup despite protections for normalized SQL section/area tables.
- **Scope dependencies.** `backend/analysis/layer2/__init__.py` registers each dependency from `rules.json`. `backend/analysis/layer2/engine.py` (`run`, `_contexts`, `_evaluate`) uses Boolean presence, compatible quantity distributions and tolerances, auto-selecting area scope if allocations exist and otherwise document scope. This can mask a room/lot shortage, flag work supplied by another package or accept incidental mentions. Each registered dependency rebuilds contexts and text maps. L2 models tender scope coverage and does not validate explicit scheduling, financial or phase graph edges.
- **Stale and out-of-order work.** `enqueue` uses `ON CONFLICT DO NOTHING` and ignores edits, cap patches and link changes. `changedFindings` handles a handful of directly edited fields. Related rows, moves, deleted rows and downstream totals can remain stale. OZ remapping can retarget a finding after renumbering or with duplicate codes. The assessment worker holds a transaction across parsing and model work, and there is no job revision, lease or retry metadata. Workspace record writes lack a per-record expected revision.
- **Financial and alert quality.** Cap meters do not enforce approvals. An award is insufficient to infer posted commitments or actuals, and an inferred cap is not an approved limit. Risk points may stack a base L2 finding, a derived change-order signal and an L3 corroboration. Review can change the aggregate score while section totals and money-at-stake remain based on the upload. Target, reason, exact expected/observed values, unit/currency, revision and next action should travel together.

## Layer 3 wiring and verification

- **Activation.** `backend/workspace_analysis.py` (`options`, `_uploaded_input`, `prepare`) accepts literal `ollama` or `anthropic` and appends 3 for eligible automatic uploads. It advertises availability by name. `backend/analysis_api.py` and `backend/analysis/__main__.py` support explicit layer requests. `backend/analysis/runner.py` defaults to layers 1 and 2. The factory in `backend/analysis/layer3/provider.py` defaults to Ollama when called directly and recognizes aliases the workspace gate rejects. `backend/deploy/compose.yaml` and `backend/deploy/compose.prod.yaml` default to `none`. `backend/deploy/.env.example` and `CLAUDE.md` document intended Anthropic use. `backend/server.py` (`health`) checks PostgreSQL only.
- **Clients and prompts.** `backend/analysis/layer3/__init__.py` orchestrates registered checks in `backend/analysis/layer3/checks/{contradictions,l2_confirm,precast,scope,underspecified,quantities}.py`. There is no standalone alert agent in that route. `backend/analysis/layer3/prompts.py` versions prompts and `schema.py` in the same directory defines structured output and item validators. Checks verify source quotes, IDs and preconditions. `provider.py` defines `LLMRequest`, `OllamaProvider` (temperature 0 and JSON schema on `/api/chat`), `AnthropicProvider` (SDK structured output, two retries on the normal path), `FakeProvider` and `ResponseCache`. Source defaults are `qwen2.5:7b-instruct`, `claude-haiku-5-5` and Anthropic audit `claude-sonnet-5-5`. Configuration includes `ANALYSIS_L3_PROVIDER`, `ANALYSIS_L3_MODEL`, `ANALYSIS_L3_AUDIT_MODEL`, `OLLAMA_HOST`, `ANTHROPIC_API_KEY` and timeout, deadline, concurrency, batch size, budget and cache settings. Code defaults include 120s timeout, 12 calls, 75s deadline and four workers. Production Compose overrides timeout and calls to 30s and 48 by default.
- **Failure behavior.** `backend/analysis/layer3/common.py` (`Session.ask_many`, `_settle`, `report`) catches provider failures and caches JSON objects before semantic validation. Empty text, invalid JSON, refusal and truncation are provider errors. Empty objects or missing/null arrays can silently look clean. `Session.dropped` is not surfaced and ordinary failed batches count as checked. Cache write errors are ignored. Shared unavailability can suppress both model roles, and reservation-time deadline checks do not stop already submitted tasks or retries. `runner.analyze` records layer 3 as entered when disabled/unavailable. `workspace_analysis.run` falls back to the requested deterministic layers on unexpected pipeline exceptions. `ListPage` relies on `layers_run`, limits error text to the first three entries and does not mark score coverage as partial.
- **Adjacent model paths.** `backend/workspace_product_ai.py` (`catalogue_provider`, `adjudicate`) and `backend/workspace_catalogue.py` (`classify`, `research_next`) use the shared wrapper for optional product matching behind `BILLBUILD_CATALOGUE_MODEL`. `backend/analysis/catalogue/{fallback,service,cli}.py` has a provider-injected catalogue workflow. These support product/price evidence. They do not call the Layer 3 alert checks. `backend/analysis/layer3/eval.py` is an explicit evaluation path with injected test providers and real-model calls from its CLI.

## Implementation and acceptance criteria

### P0 · Integrity, report freshness and visible AI failure

1. **Validate graph inputs before calculating.** Add a shared validator near `backend/analysis/adapter.py`, wired through `runner.py`, `workspace_analysis.prepare` and the L1/L2 consumers. Index typed references, detect cycles and report edge kind, IDs and source provenance. Exclude invalid calculations and gate unsafe publication while preserving diagnostics.  
   **Accept** valid out-of-order parents and deep trees. Test self-links, long and short cycles, bad alternative chains, missing parents, orphan positions/allocations, cross-scope links and disconnected components. Invalid branches must not be reported as authoritative zero. Unaffected valid results stay available.
2. **Version effective snapshots and publish conditionally.** Target `backend/workspace.py`, `backend/workspace_analysis.py`, `backend/server.py`, a new migration and `frontend/src/lib/risk-assessment.ts`. Bind runs to relevant original, edit, link and cap revisions. Preserve source evidence, coalesce work, claim in a short transaction and provision bounded retries. Display stale, partial and failed states, including the normalized BOM outdated response.  
   **Accept** integration fixtures for first import, delayed file, edit/add/move/delete, cap/link changes, duplicate delivery, rollback, retries and out-of-order workers/clients. Older runs cannot overwrite current results or drive an actionable fix. Unchanged evidence retains reviewer decisions.
3. **Normalize L3 routing and expose true outcomes.** Update `backend/analysis/layer3/{__init__,common,provider,schema}.py`, both analysis routes, Compose and report/UI types. Publish structured disabled, no-candidates, complete, degraded and unavailable states with planned/attempted/validated/cached/failed/skipped/dropped counts and sanitized reasons. Separate provider roles where meaningful. Keep deterministic findings usable throughout.  
   **Accept** offline worker/route tests for default-off, explicit activation, misconfiguration, valid empty arrays, missing/null envelopes, rejected evidence, timeout and unexpected crashes. The score and exports visibly distinguish rules-only, partial and completed analysis. Default health checks use configuration and local state without model calls.

Analysis, UI and export agree on representative priced fixtures.

   **Accept** fixtures for reused stems, renames, reordered/ambiguous OZ, wrong package/currency, duplicate award, phase regression, exact cap boundary and suggested versus approved amounts.
